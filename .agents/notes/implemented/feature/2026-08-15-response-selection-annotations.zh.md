# Agent Note: 回复选区批注

Status: implemented

[English](2026-08-15-response-selection-annotations.md) | 中文

## 问题

读者要质疑 Assistant 回复中的某一小段内容时，必须手动复制摘录、保留足够上下文，再返回输入框。偏网页端的大字号也让桌面侧边栏里的长篇技术回复更难快速浏览。

## 决策

Assistant Markdown、表格、推理摘要、用户气泡和输入框使用紧凑的桌面端字号。选区完全位于一条 Assistant 回复内部时，选区附近会打开固定定位的批注编辑器。确认后，摘录会被格式化为 Markdown 引用，再加上本地化批注标签和读者评论，追加到对应会话的现有草稿，并将输入焦点放到草稿末尾。该操作绝不自动发送。

视图为每个会话注入一个稳定的 `appendAnnotation` 回调。聊天行获得该回调但不订阅草稿 store，因此输入框中的每次按键不会重新渲染回复行。按 Escape、点击外部、滚动或调整窗口大小会关闭编辑器且不改动草稿。

## 考虑过的替代方案

**立即发送批注。** 这会跳过检查步骤，并可能发送未写完的评论或误选的摘录。把批注留在输入框中可保留正常的编辑和发送路径。

**保存专有的回复引用对象。** 当前提示词和会话日志不需要新的持久格式，因为普通用户文本中的 Markdown 引用已经保留所需上下文。如果模型或 transcript 将来需要稳定的回复身份，再引入结构化引用。

**让每条聊天行订阅输入框状态。** 这会让回复渲染跟随草稿的每次按键。会话级注入回调提供写入能力而不增加该订阅。

## 影响

批注可继续编辑，经现有用户消息路径进入 replay，不需要改变模型输入格式或持久化格式。选区不能跨越不同 Assistant 回复根节点；没有提供输入框回调时，批注编辑器会保持不可用。聊天视图测试覆盖 DOM 选区行为，注入回调测试覆盖草稿追加和焦点归属。
