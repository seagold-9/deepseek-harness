# Agent Note: 回复选区批注

Status: implemented

[English](2026-08-15-response-selection-annotations.md) | 中文

## 问题

读者要质疑 Assistant 回复中的某一小段内容时，必须手动复制摘录、保留足够上下文，再返回输入框。偏网页端的大字号也让桌面侧边栏里的长篇技术回复更难快速浏览。

## 决策

Assistant Markdown、表格、推理摘要、用户气泡和输入框使用紧凑的桌面端字号。鼠标选区从一条 Assistant 回复内部开始时，浏览器选区会保留，并在鼠标松开位置旁打开固定定位的操作菜单；即使鼠标在回复边缘之外松开，该选区仍会被识别。这个终点锚点让操作入口在选区跨越多行、段落或表格单元格时仍靠近用户最后操作的位置。选择**添加到对话**后，批注编辑器才会在同一锚点打开，评论可以留空。确认后，摘录会被格式化为 Markdown 引用；仅在存在评论时添加本地化批注标签，再追加到对应会话的现有草稿，并将输入焦点放到草稿末尾。原回复不会保留高亮或引用编号，确认操作绝不自动发送。

视图为每个会话注入一个稳定的 `appendAnnotation` 回调。聊天行获得该回调但不订阅草稿 store，因此输入框中的每次按键不会重新渲染回复行。按 Escape、点击外部、滚动或调整窗口大小会关闭菜单或编辑器且不改动草稿。此应用不存在第二聊天目标，因此不渲染侧边聊天操作。

## 考虑过的替代方案

**立即发送批注。** 这会跳过检查步骤，并可能发送未写完的评论或误选的摘录。把批注留在输入框中可保留正常的编辑和发送路径。

**保存专有的回复引用对象。** 当前提示词和会话日志不需要新的持久格式，因为普通用户文本中的 Markdown 引用已经保留所需上下文。如果模型或 transcript 将来需要稳定的回复身份，再引入结构化引用。

**在被引用的回复文字上保留带编号的高亮。** 多条批注需要会话级编号，并明确草稿编辑、删除、发送、transcript replay 和重复摘录时的行为。会重置或在无关时机消失的临时标记会误导用户，因此引用进入输入框后，原回复保持不变。

**让每条聊天行订阅输入框状态。** 这会让回复渲染跟随草稿的每次按键。会话级注入回调提供写入能力而不增加该订阅。

## 影响

批注可继续编辑，经现有用户消息路径进入 replay，不需要改变模型输入格式或持久化格式。用户选择批注操作之前仍可使用普通浏览器复制。选区不能跨越不同 Assistant 回复根节点；没有提供输入框回调时，批注操作会保持不可用。聊天视图测试覆盖局部选区、相对终点的定位、在回复外松开的整段拖选和可选评论，注入回调测试覆盖草稿追加和焦点归属。
