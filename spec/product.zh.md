# dsh 产品规格

[English](product.md) | 中文

状态：草案

更新时间：2026-08-15

## 产品定义

`dsh` 是一个基于官方 DeepSeek Harness 的非官方桌面发行版，目标是在保留官方 Agent 能力和配置方式的前提下，提供安静、紧凑、可长期使用的桌面工作界面。

产品首先服务于个人探索和 DIY，也应当具备足够清晰的安装、配置和迁移体验，使没有本地开发环境的用户能够在输入 DeepSeek API Key 后直接使用。

## 核心原则

- 官方能力优先：Agent 运行、模型接入、会话和插件体系尽量沿用官方实现。
- 桌面体验优先：用户不需要打开浏览器、终端或手动启动后端。
- 定制分层：桌面壳、视觉主题和独立交互功能保持可识别，降低合并官方更新的成本。
- 本地数据可控：用户知道数据存在哪里，也能明确导出、迁移或清除。
- 稳定胜过追新：每个桌面版本绑定一个验证过的官方提交或版本，不在启动时自动拉取未知代码。
- 诚实标识：未获得 DeepSeek 授权前，发行版明确标注为非官方项目。

## 目标体验

1. 用户从 Windows 安装包或便携包启动 `dsh`。
2. 应用在任务栏显示独立图标和窗口，不出现浏览器地址栏或终端窗口。
3. 应用自动启动内置的 DSH 后端，等待健康检查成功后展示界面。
4. 首次使用沿用官方界面输入 API Key，密钥不会出现在日志、导出包或 Git 中。
5. 退出最后一个窗口后，应用有序停止由它启动的后端进程。
6. 用户可导出适合迁移的数据，并在另一台电脑导入后重新连接本地工作目录。

## 视觉与交互方向

- 使用黑白鱼形标志和 `探索未至之境` 作为保留的品牌识别元素。
- 整体采用紧凑、中性的桌面工具风格，避免大字号、大胶囊、高饱和蓝色和网页文章式留白。
- 会话、工具调用、Markdown 和输入区优先服务于扫描、比较和重复操作。
- 保留选中 Assistant 文本后添加批注并送入输入框的交互。
- 后续交互应优先使用桌面惯例，例如快捷键、右键菜单、紧凑悬停操作和稳定的多栏布局。

## 第一阶段范围

- Windows x64 桌面客户端。
- 安装版和便携版两种交付物。
- 自动管理单个本地 DSH 后端。
- 沿用官方 DeepSeek API Key 配置和官方 Web 功能。
- 当前 UI 定制与文本批注能力。
- 明确的数据目录、诊断日志、升级和迁移流程。

## 暂不做

- macOS、Linux 和移动端正式发行。
- 自建账号、云同步或远程会话托管。
- 自动迁移任意电脑上的绝对工作目录路径。
- 绕开官方 DSH 接口重写 Agent 核心。
- 在未确认商标授权前以“DeepSeek 官方客户端”名义发布。
- 第一版内实现应用自动更新；先建立可回退的手动升级流程。

## 成功标准

- 一台没有预装 Node.js 或 pnpm 的 Windows 电脑可完成安装并启动。
- 首次启动能在界面内完成 API Key 配置并创建一次正常会话。
- 窗口关闭、后端异常、端口冲突和重复启动都有明确且可恢复的行为。
- 用户数据在应用升级后保持可用，卸载时不会未经确认删除。
- 安装包、便携包和迁移包均不包含 API Key。
- 每个发行版本都能追溯到明确的官方 DSH 基线和本项目提交。
- 官方 DSH 更新后，可按固定流程评估、合并、验证并保留选择的定制。

## 发行命名

应用显示名暂定为 `dsh`，包名、可执行文件名和 Windows App User Model ID 在首次桌面实现前固定，避免后续升级被系统识别为另一个应用。

黑白鱼形标志可用于个人原型；对外分发前必须单独确认 DeepSeek 名称和标志的商标、品牌使用许可。源码的 MIT 许可不自动授予商标权。
