# dsh 路线图

[English](roadmap.md) | 中文

状态：计划中

路线图描述顺序和完成条件，不承诺具体发布日期。每个阶段通过验收后再进入下一阶段。

## 阶段 0：项目基线

状态：进行中

- 建立 `spec/`、产品边界、架构决策和上游更新流程。
- 把现有 UI 定制整理成可审查的提交序列。
- 建立个人 GitHub fork，并把官方仓库配置为只读 `upstream`。
- 固定当前官方基线、Node/pnpm 版本和验证命令。

完成条件：另一位开发者仅阅读仓库文档，就能区分官方代码、现有定制和计划功能，并能复现当前 Web 开发环境。

## 阶段 1：桌面技术验证

状态：未开始

- 新增最小 Electron 工作区应用。
- 启动官方 DSH 子进程并加载其回环 Web UI。
- 验证动态端口、就绪探针、优雅退出、重复启动和后端崩溃恢复。
- 验证生产打包后插件、静态资源和 Node 运行时完整可用。
- 建立最小安全基线和导航限制测试。

完成条件：一台未安装 Node.js 的测试电脑可以启动打包后的原型、配置 API Key、完成会话并干净退出。

## 阶段 2：可日常使用的 Alpha

状态：未开始

- 接入应用图标、独立任务栏身份、窗口状态恢复和单实例行为。
- 完成启动、加载、后端错误、端口错误和恢复界面。
- 固化 `DSH_HOME` 路径和升级行为。
- 保留当前紧凑 UI 与文本批注功能。
- 增加脱敏日志和一键打开诊断目录。

完成条件：连续使用、重启和异常退出不会丢失会话，常见故障不需要打开终端处理。

## 阶段 3：可迁移 Beta

状态：未开始

- 实现带版本清单的导出、校验、备份和导入。
- 默认排除凭据、日志和缓存。
- 为缺失工作区提供重新连接流程。
- 生成 Windows x64 NSIS 安装包和便携 ZIP。
- 在干净虚拟机执行安装、升级、卸载和迁移测试。

完成条件：用户可以把非敏感 DSH 数据迁移到另一台电脑，并在重新输入 API Key、连接工作区后继续使用。

## 阶段 4：可对外分发

状态：未开始

- 确认名称、标志和非官方声明的使用方式。
- 配置 Windows 代码签名、发布校验和校验和文件。
- 建立发行说明、已知问题和回退步骤。
- 至少演练一次完整的官方 DSH 上游升级。
- 决定是否加入应用内更新；没有可靠签名和回退前不启用。

完成条件：非开发用户能理解安装警告、配置应用、升级或回退，发布物可追溯且不携带开发者或测试用户数据。

## 后续候选

以下项目处于待决定状态：macOS 发行、Linux 发行、系统凭据库、应用内自动更新、多窗口、托盘常驻和定制插件市场。它们需要独立规格，不能直接混入第一版。
